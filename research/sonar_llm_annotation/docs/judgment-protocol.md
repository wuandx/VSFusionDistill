# 声呐判定卡 · 判读协议（T-CARDS）

本文件是判定卡（`engine/cards.py` 渲染的三联图）**唯一**的判读口径。
读者：看卡片做标注的视觉模型，以及复核它的人工标注员。
卡片只提供证据与尺度，**不提供结论**；结论由本协议推导。

版本：`cards/v1`（卡片右上角 `cards/v1`；改动版式必须同时改本文件）。
词表 v1.1：与 `plugin/sonarllm/judge.py` 的 `VERDICTS` 对齐（`object / structure / unsure / empty`）。
旧稿的 `target / absent / uncertain` 已废弃，落盘只认这四个值。

| verdict | 含义（与 judge.py `_VERDICT_HELP` 一致） |
|---|---|
| `object` | 扇面内存在与背景结构可分离的、离散的、有边界的高亮回波 |
| `structure` | 只有贯穿扇面／延伸到边缘的大尺度结构，没有可定位的离散目标 |
| `unsure` | 有迹象但不足以判定（必须说出卡在哪一步，见 §4） |
| `empty` | 扇面内没有显著高亮回波 |

---

## 0. 一句话

> 一条亮弧（镜面反射主瓣）**不是目标**。
> 目标是叠在这条弧上、**局部更小更亮**、在连续多帧里保持同一径向位置的那一小块。

**框住类无关结构 = 错误标注。**
（本项目实测：100 lbs 航空炸弹、15 cm 迫击炮弹、20 lbs 燃烧弹三类目标的标称尺寸差近 4 倍，
但主回波的角宽与径向厚度几乎相同，径向只有 0.32–0.33 m。也就是说，"这条贯穿大半个扇面的亮弧"
对三类目标是同一个东西，它是**类无关结构**，不含类别信息。本轮抽看的帧里这条弧无一缺席，
而目标只在其中少数帧里以一个小而亮的局部扰动出现。）

## 1. 卡片上每个元素是什么意思

横向三联，左→右，底部一行信息条。整卡共用**同一次**灰度拉伸（锚点取全帧 p0.5–p99.5），
所以 B、C 两栏的光度可以直接互相比较，A 栏因为是整幅缩略图，只能看位置不能比亮度。

| 栏 | 内容 | 你能从它得到的 |
|---|---|---|
| **A** | 整幅原始帧，按高度铺满（`A FRAME 宽x高`）。带青色候选标记、灰色虚线裁剪窗 | 目标在这帧的**绝对位置**；裁剪窗是否贴边被裁（`clipped L/R/T/B`） |
| **B** | 裁剪窗的整数倍放大（`B CROP x N m40`），像素为精确整数复制，未插值、未锐化 | 回波的**形状与内部层次**；候选标记 vs 真实亮头的偏差 |
| **C** | 同一张裁剪 + 尺度尺（无剪影时 `C SCALE (no prior)`，右上角 `prior: unavailable`） | 回波的**真实米制尺寸**（径向） |
| **D** | B、C 下方的**时间条**：同一裁剪窗，±2 帧共 5 格，左→右帧号递增，当前帧橙色边框 | 亮头在**时间上**是否连续、径向漂移多少（判据 a2） |

B 栏有两种取景，**用 caption 区分，不要混**：

* caption **没有** `ROI only`、画面里有**青色框** = 这一帧有候选，B 围着候选裁；
* caption 写 `ROI only (no candidate)`、画面里**没有青色框** = 这一帧引擎没给候选，B 改为围着
  **结构区**（class-agnostic 回波带）裁，只为把"这里到底有没有目标"放到能看清楚的倍率下。
  ROI 是**取景窗，不是检测**：它画在 A 栏是灰色虚线框，从来不画成青色候选框。

标记与颜色（legend 行原样写在卡片上）：

| 元素 | 含义 | 能不能当证据 |
|---|---|---|
| 青色实线框 `candidate` | 上游给出的候选框，**只是一个提议** | 位置可参考；**尺寸不可信**，必须自己复核 |
| 只有灰色虚线裁剪窗、没有青色框 + caption `ROI only (no candidate)` | 这一帧引擎没有候选，B 的取景窗落在一个结构区上 | 只能说明"这里需要判"，**不代表有目标** |
| 青色圆圈 + `ring = no extent` | 候选小于 3 px，没有可画的边界，只标中心 | 只能当定位点；**不能**说它框住了本体 |
| 紫色虚线框 | 同一帧里 rank 1–2 的其它回波团 | 用于判断"是不是多目标重叠" |
| 灰色虚线框 + 四角角标 | B 栏取的是 A 栏的哪一块 | 用来确认 B 没切掉回波 |
| 灰色虚线十字 + `gantry hypothesis (refuted)` | 万不得已画出的 gantry 反推位置 | **不是证据**。已在本数据上被证伪，默认不画 |
| 白色刻度 / 白色横条 / `dR x.xx m` | 米尺、尺度条、候选框的径向厚度 | 是**测量**，不是判据 |
| 橙色 `prior: unavailable` | 没有剪影可用 | 该类目标只能判存在性与粗框，不能判姿态 |

底部信息条第一行是 `sample | category | range_m | candidate.source | engine_version`。
`range_m` 现在是 `UNRESOLVED (gantry_not_sonar_frame)`：**不给数字**。gantry 反推（圆形轨道、
残差 11–17 mm、整条录音方位角只转 0.32 圈）已在本数据上被证伪，一个看起来像测量值的数写在这里
会被当成证据。要距离就自己从 C 栏米尺读。
`candidate.source NONE (empty proposal; B frames a structure ROI)` 的意思是这一帧没有候选，
不是渲染失败 —— 它可以合法地对应 `empty` 或 `structure`。

### 1.1 怎么读尺度（C 栏）

* 左侧竖刻度是**径向距离**（米），由 `WindowStart + row × 0.002983 m` 算出，`0.002983 m/行` 来自 `aris_frame_meta.csv` 的 `WindLng`/`SamplesPerBeam`，并与 `c·SamplePeriod/2` 交叉校验。
* 底部白色横条标出 `0.10 m of range`（一个刻度格对应的真实米数），是纯比例参考。
* `dR x.xx m` 是候选框的径向厚度（`(y1-y0) × 0.002983`），**这是唯一可以直接读出来的目标尺寸**。
* `L 0.737 m = 247 rows` 是标称长度换算：目标若真有这么长，需要 247 行，而当前裁剪只有 230 行左右
  （放得下时会追加 `= 1.1x crop`）。标称长度取 `mesh-registration.json` 的 `nominal_length_m`：
  `100lbs_aircraft_bomb 0.737 m`、`mortar_shell 0.580 m`、`incindiary_grenade 0.442 m`
  （卡片标 `(nominal, intact round)`；真有剪影时改由 `prior.length_m` 给出）。
  它只能用来问"这个亮块够长吗"，**不能用来定类别** —— 三类相差近 4 倍，但主回波角宽与径向厚度
  几乎相同（径向 0.32–0.33 m）。
* 横向（方位）**没有**米制刻度：`aris_file_meta.yaml` 只给 `NumRawBeams=128`，没有扇面角，横轴像素无法换算成度或米。
  所以**不要**从横向像素宽度推目标长度。

### 1.2 怎么读时间条（D 栏）

时间条是同一裁剪窗在 `当前帧±2` 上的 5 格展开（`--neighbors 2`，默认开）。各格与主卡**共用同一拉伸锚点**，
所以亮度可以直接比。格顶黑底小牌是帧号，**橙色边框那格就是当前帧**。
某格写 `no frame` 表示该帧在磁盘上不存在（录音首/尾之外），这是证据缺口，不许用相邻帧顶替。

怎么用它判 a2：

1. 在 5 格里找同一个亮头：它应沿**径向**（竖直方向）基本停在同一条带上。
2. 5 格内径向漂移合计 0.05–0.15 m 属正常（约 17–50 行）；超过 0.30 m 说明它每帧换地方，多半是噪声。
3. 亮头若在时间条里**忽隐忽现**，但每次出现都在同一位置 → 仍算时间一致（可能是姿态闪烁）。
4. 亮头若**横向**（沿弧）滑动而径向不变 → 是结构在动（平台/水面），不是目标。
5. 时间条整体过暗或过亮（`no frame` 之外全是 255/黑）→ 该帧集合不能用于判读，`unsure`。

## 2. 判据 (a)：目标存在性

三条**同时**满足才可判 `object`；缺一条则 `unsure`（见 §4）；三条都否且能确认回波来自结构/噪声则 `structure` 或 `empty`。

**a1. 强回波。** 候选区域存在局部亮于背景的回波：
* 相对量：候选峰值 vs 其 31×31 邻域背景（卡片拉伸后的视觉判据：亮头明显亮于周围弧体，且**有内部层次**，不是一个均匀的白块）；
* 绝对量参照：`stretch` 行给出 `lo/hi`。候选峰值应显著高于 `hi`（即达到饱和肩部），
  而背景噪声中位数落在 `lo`–`hi` 之间。
* 反面：只有斑点噪声、或亮度与背景涨落同量级 → a1 不成立。

**a2. 与预测位置一致。**
* 若卡片**画了**十字（`predicted.available = true`，来自声呐帧自身估计）：候选中心与十字的距离应在候选自身尺寸的 ~1 倍以内。
* 若卡片**没画**十字（当前默认），则"位置一致"改由**时间条（D 栏）**承担，见 §1.2：
  候选在相邻帧里径向位置相近（同一条录音内漂移应在 0.05–0.15 m 量级），
  即它不是每帧随机跳到另一处噪声点。时间条里亮头忽左忽右、忽上忽下 → a2 不成立。
* **禁止**把 gantry 反推的 `range_m` 当作 a2 的证据；那条推断已被证伪（`gantry_not_sonar_frame`）。

**a3. 形状与尺寸先验相容。**
* 形状：镜面反射主瓣呈**局部凸起的小亮头**（端部亮度最高），可带短尾翼状回波；
  能确认的尾翼与端部应被框**在内**（见 §3）。
* 径向厚度：`dR` 的经验区间（本项目实测统计，**非论文事实**）是 0.03–0.35 m。远小于 0.03 m 的多半是单个噪声亮点；
  远大于 0.35 m 的多半是弧体本身（类无关结构）被整体框住。
* 与 `L` 的关系：若 `dR ≈ L`（目标径向厚度约等于标称长度），说明框的是"躺着的一条亮带"，
  多半就是类无关结构，此时**必须** `unsure`，不得直接判 `object`。

## 3. 判据 (b)：怎么框住本体

框的语义：**框围目标本体，含可确认的尾翼与端部；不包支架、阴影、多径。**
具体操作顺序：

1. **先分离"结构"与"扰动"。** 沿亮弧走一遍：这条亮带是否**连续延伸**到裁剪之外（或被 `clipped` 标出的帧边界）？
   若是，它是结构。目标是在这条带**内部**或**端部**凸出来的那一小块——
   它比带体亮、比带体厚、边界更"鼓"。最快的判别法子是**时间条**：
   整条带在 5 格里整体平移＝结构；某个小亮结在 5 格里钉在同一径向位置＝目标。
2. **框贴在镜面反射主瓣上。** 框的短边应贴住亮头的**上、下边界**，不要让框有一半落在暗背景里；
   框的长边沿亮头**端部边界**收口。
3. **覆盖端部亮头。** 主瓣最亮处通常在端部（"亮头"）。框必须**完整包含亮头**，
   不要把亮头切成一半、也不要只框住亮头的一小块亮斑。
4. **不要框住整条尾迹。** 亮头后面拖出的暗淡尾巴（尾迹/多径/气泡羽流）不算本体。
   若尾迹明显（长度 > 3× 亮头），只框亮头部分。
5. **不包支架、阴影、多径。** 支架是细长、位置固定、跨帧不变的回波；阴影是亮头**紧邻**的低回声暗区；
   多径是亮头在径向上以整数倍距离重复出现的弱影。这些一律排除在框外。
6. **自检三个数**：框的 `dR`（径向厚度）、框长边沿弧方向的像素数、`dR/L` 比。
   若 `dR` 接近 `2.4x crop` 量级（即框比裁剪还高）→ 框错了，重来。

**错误示例（本批真卡片里出现过）：**
* `2023-09-20_171105_0900`：候选框 100×22 px，横跨整条弧 → **框住了类无关结构**，错误标注。
* `2023-09-21_120653_0163`：候选只有 1×4 px，卡片用圆圈标出并写 `no extent` → 这种帧不许硬框，应 `unsure`。
* `2023-09-20_171105_0622`：框只盖住亮头顶部的一小块（12×9 px）→ 框得太小，漏掉端部亮头，需扩到亮头边界。

## 4. 判据 (c)：什么时候**必须**答 `unsure`

出现下列任一情形，答案只能是 `unsure`，并在 `reason` 里写明命中的是哪一条（c1–c8）。
**不允许**用"看起来像"去补一条证据。

| # | 情形 | 卡片上的识别信号 |
|---|---|---|
| c1 | **预测越界** | 十字缺席且 footer 写 `pred NOT DRAWN`；或十字旁 `pred: OUT OF WINDOW`；候选落在裁剪窗之外 |
| c2 | **近场饱和 / 底混响淹没** | 亮头区域整片均匀 255、无内部层次；或底部几十行被标 `bg band`；或 `stretch` 的 `hi` 极低（如 < 20）导致整幅发灰 |
| c3 | **多目标重叠** | 同一裁剪内 ≥ 2 个紫色虚线框，且与青色候选互相接触或叠压 |
| c4 | **仅凭尺寸无法区分类别** | `dR` 相近（见 §2 a3）、`L` 只有标称值（`(nominal, intact round)`）、且 `prior: unavailable` → 无法在 100lbs / 迫击炮弹 / 燃烧弹之间定位 |
| c5 | **候选退化** | `ring = no extent`、`cand degenerate 1x4 px -> ring marked, no extent claimed` |
| c6 | **没有可辨识主瓣** | 回波只是一团弥散羽流、或一串彼此分离的小亮点（早期帧常见），沿弧找不到"鼓起来"的局部 |
| c7 | **回波被帧边界切掉** | B 栏 caption 有 `clipped L/R`，且亮头贴在被裁的那一侧 → 无法确认端部 |
| c8 | **没有剪影但被要求判姿态/类别** | `prior: unavailable`；姿态角、类别、朝向一律 `unsure`（存在性仍可判） |

补充纪律：

* **一卡一判**：一次只判青色标记所指的那一个候选。多个候选要分别判，不许合并。
* **不猜**：卡片上没有的元素（方位角、扇面角、深度）不存在于证据里，不许推算后写进结论。
* **卡片的装饰不是回波**：米尺、图例、信息条、`prior: unavailable` 徽标都是叠加图形，不参与判读。
* **灰度只用于看结构**：`gain 1/3/5×` 只改显示增益，不改变相对关系；同一帧不同 gain 的结论必须一致，
  不一致说明你在读显示而不是读数据。

## 5. 输出格式

```json
{
  "sample": "2023-09-20_171105_0622",
  "verdict": "object | structure | unsure | empty",
  "shape": "point | short_arc | streak | blob | none",
  "box": [x0, y0, x1, y1],
  "discrete_object_present": true,
  "structure_present": true,
  "structure_overlap": 0.0,
  "reason": "亮头在时间条 5 格里径向稳定，框住端部亮头；重叠的亮弧已排除在框外",
  "confidence": 0.0,
  "judge_model": "<模型名>",
  "card_sha256": "<读的那张卡的 sha256>"
}
```

* 字段与 `plugin/sonarllm/judge.py` 的 `JUDGE_SCHEMA` 完全一致，多一个字段都会被判为不合格。
* `box` 用**帧像素坐标**（与卡片 footer 的 `box`/`crop win` 同一坐标系），`x`=beam 0..127，`y`=row；`verdict != object` 时通常给 `null`。
* `shape`：单个亮点 `point`／短亮弧 `short_arc`／细长拖尾 `streak`／面状亮团 `blob`／无 `none`。
* `verdict = structure` 必须能说明那条结构是什么（贯穿扇面的镜面反射带／支架／多径），`structure_overlap` 给出候选框与结构的重叠比例。
* `verdict = empty` 表示扇面内没有显著高亮回波；`verdict = unsure` 必须写明 c1–c8 之一。
* `card_sha256` 必须等于你读的那张卡的实际 sha256（卡片 meta 的 `out_sha256`），防止图和结论对不上。

## 6. 可复现性

* 同一 `frame_data` 两次渲染**逐字节一致**（selftest `deterministic PASS`；已用真帧交叉验证：
  `out/cards/2023-09-21_100927_0524.png` 重渲一次 sha256 相同）。
* 每张卡的 `meta` 记录 `image_sha256`、`out_sha256`、拉伸锚点与 shoulder 参数、裁剪窗与边距、
  `row_scale` 来源、`temporal`（时间条用了哪些帧、哪些缺）、`candidate_degenerate`。
* 产物路径：`out/cards/<sample>.png`，`sample = <recording>_<frame:04d>`，与 manifest 的 `sample` 一致；
  汇总在 `out/cards/report.json`（`frames` 给出三条录音的**冻结帧表**，`cards[].out_sha256` 是每张卡的
  sha256，`provenance` 写引擎与生成方式）。
* 本轮池（**已冻结**，36 张）：三条录音各 12 帧，在该录音实际帧区间上均匀取、两端点含，
  全部来自 manifest 的开发行（`paired_role ∈ {train, val, val_id}`，**不含 test**）。
* 候选/取景口径：候选来自 `engine/echo.py`（`analyse_frame(mode=local)`、`bg.half=10`）。
  `out/<rec>/proposals.jsonl` 只覆盖每条录音的前 100 帧，所以跨首尾的帧由
  `tmp/cards/gen_proposals.py` 用**同一入口**重算（已核对与之逐帧一致：bomb 622/700/721 的
  blob box、structure 数、bg window 全同）。`candidate_distribution` = `{0: 30, 1: 6}`：
  30 张卡的 B 栏取结构区（`ROI only (no candidate)`），6 张有候选。
* 复现一条命令：
  `python tmp/cards/gen_proposals.py --recording <rec> --frames <a,b,...>` 之后
  `python tmp/cards/make_out_cards.py`
  （单卡调试用 `python engine/cards.py --proposals <p> --out <dir> --flat --neighbors 2`；
  `--gain 1,3,5` 加 `__g<gain>x` 后缀；`--neighbors 0` 关时间条）
* 判读侧配套：`plugin/sonarllm/judge.py` 的 `JUDGE_SCHEMA`；落盘前用它的校验函数查 `verdict / shape / box`。
