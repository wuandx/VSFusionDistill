# 原因追查与CMHD对齐：gantry时间对应的新证据

2026-11-12。执行`sonar_motion_timing`、`sonar_source_onset_control`；[运动审计计划](../../experiment/archive/sonar-motion-timing-plan.md)、[对照计划](../../experiment/archive/sonar-source-onset-control-plan.md)。**本轮找到可以解释普通bomb部分错位的具体时间对应差异，而不是继续拟合模型/外参。尚未认证全数据修复，也未部署新时间版本。**

## 事实：两条bomb的时间偏移不同于源运动起点

限定此前六条允许开发录音。检查processed原ARIS metadata/marks/flow、gantry位置CSV、matches与gantry_metadata。官方以ARIS onset为基准，gantry时刻为：

`gantry_start + gantry_offset + (aris_frame_time - aris_onset_time)`。

原gantry首个非零XY位移、官方dx+dy非零判据和gantry_metadata给出的运动起点一致；六条均无时间倒退，未发现首运动被dx+dy抵消的错误。ARIS marks onset也与matches相同。但matches的gantry_offset如下：

| recording | matches offset | 原gantry首运动offset | matches相对首运动 |
|---|---:|---:|---:|
| 171105 bomb | 4.251532s | 10.390999s | 提前6.139467s |
| 173329 bomb | 4.248250s | 6.000000s | 提前1.751750s |
| 100927 mortar | 8.859000s | 8.859000s | 一致 |
| 101131 mortar | 3.640001s | 3.640001s | 一致 |
| 120653 grenade | 3.968999s | 3.968999s | 一致 |
| 120912 grenade | 4.047001s | 4.047001s | 一致 |

这是原始记录复算事实，不是用目标回波优化出的时偏。**它不自动证明matches错**：ARIS可因手动pan先发生图像运动，人工可能有意调整offset；缺乏历史调整理由。仅有一侧gantry首运动仍不足以认证两传感器物理同步。完整[审计JSON（本地产物说明）](../../ARTIFACTS.md#artifact-cf4d3c0985b8)保留原记录、flow前后窗口、时间和来源hash。

## 受控实验：只换成源运动起点，不动模型和角度

固定旧18开发身份；用源gantry首运动offset替代matches值，其余ARIS onset、pan/tilt/roll、外参、target、旧PCA模型、尺度、图像、观察全部不变，不进行mesh/时间/角度拟合。

171105三帧相机/声呐共同位姿的平移变化为0.2942、0.3063、0.2532m，沿轨迹相位变化14.36°、15.43°、12.27°。这与上一轮拟合的+12.93°pan处于相同量级，**支持那个角度可能在补偿时间对应造成的位置偏差**，不能将它称为测得的声呐固定角误差。173329三帧位移0.0821、0.0868、0.0615m，相位差约2.95–4.35°。

同一旧PCA模型的三帧完整投影对旧回波观察的容许带覆盖为：

| 171105帧 | 原matches时间 | 源运动起点时间 |
|---|---:|---:|
| 0622 | 0% | 50% |
| 0981 | 71.4% | 100% |
| 1336 | 0% | 81.8% |

这是仅顶点凸包、2beam/5bin容许带的诊断，**不是GT IoU、自动框接受率或完整声学渲染**。三帧粗位置目视改善，但0622/1336仍有边界/范围不一致。第二条录音0154仍明显错位，0916有局部改善、仍未通过；0456无可靠回波，继续uncertain。全部六张均已查看，失败保留。[左右对照（本地产物说明）](../../ARTIFACTS.md#artifact-4cd2c1c094b9)：左旧matches，右源运动起点，模型完全相同。

## 跨模态与去模型控制

旧17张camera端部观察保持同样的两帧三维点拟合与其余帧检查协议。没有用camera数据选择时间或角度。

- bomb的首末fit端点欧氏误差中位数76.87→8.92 SD px；**未参与拟合的同录音0981两端误差**从13.42/55.16变成13.39/6.95px，中位数34.29→10.17px。
- bomb全部非fit camera检查的中位数143.66→102.63px，但最大值391.57→570.99px，跨录音仍有严重失败。不能只报中位数下降。
- 另四录音offset不变；grenade/mortar检查结果数值不变，是负对照。当前K/端部对应仍未经完整物理校准，相机控制只能支持或反驳，不能单独认证同步。

再复算上一轮同一端部区域的两视角反投影，完全去掉mesh、尺度和target：尾颈B从原时间下数值最近约0.4727m，变成可以找到距离<1.3e−8m的共同世界点，两个seed均找到。**这解释了上一轮“尾颈不相容”如何由gantry时间对应引起，而不需要移动mesh。** 圆头A仍约0.1597m不相容；A存在FOV截断、亮边不一定为真实轴端，其对应不被认证。两seed差分进化均达200代上限，success=false保留；B的显式可行点证明该区域可相交，但不证明真实物理对应、唯一位置或全局注册成功。

## 原因判断与纠正

1. 已确认两条bomb的matches offset与独立源gantry运动起点不同，并且足以产生厘米至几十厘米位置差。
2. 对171105，源运动起点对照同时改善声呐粗位置、同录音camera检查，并消除了尾颈区域的跨帧不相容。**时间对应是有多项证据支持的原因候选**，比单一mesh原点或全局pan错误更能解释这部分现象。
3. 第二录音、圆头对应和其他类的完整注册仍未解决。缺乏ARIS与gantry共同独立运动事件的物理确认，不能把源onset替代值立即定为正式同步修正。
4. 更正此前工作的证据边界：复算官方导出链相同，不代表同步/位姿物理正确；旧PCA与fit失败也不能全部归因缺少mesh注册。旧报告保留，本报告明确补充这个遗漏。

下一步应在允许范围内核实ARIS onset附近的**平移运动**，分离手动pan造成的变化，并检查跨录音姿态/异常；通过后冻结时间版本，再重新执行固定注册。不能使用已在旧时间链上拟合的mesh变换直接追认新版本，也不能通过逐帧移动模型弥补。无需等待作者作为硬前置。当前不部署新offset、不训练、不使用test、不改变split或正式GT。

## 2026-11-12 后续更正：gantry首变化样本不等于物理起点

六条源gantry在最后静止记录至第一条位置变化记录之间均存在2.09–2.19秒空档。此前“首运动”应限定为“首次记录到位置变化”；不能据此认证精确时间误差。第二段173329用户确认播放器约00:03已持续移动，对应ARIS画面t约+1秒，落在旧映射的取样空档[−.43625,+1.75175]秒内，不证明旧时间必错1.75175秒。源onset对照及其几何改善仍保留为诊断，不能冻结同步。见[完整取样审计](sonar-gantry-onset-sampling-audit.md)。


## 2026-11-12 来源历史再更正：差值已有软件机制，非独立同步证据

[gantry空档来源审计](sonar-gantry-gap-origin.md)证实首变化样本与metadata onset同源，不能当两次独立测量。官方2023-10-19已因为considerable delay采用首变化行；两bomb旧matches又精确满足官方GoPro/gantry偏移联动规则。原6.139467/1.75175秒是首变化样本与matches的差，不是已测得的物理同步错误。原源onset对照改善仍仅诊断，不部署，不重新注册；真实bag与控制状态尚未取得。
