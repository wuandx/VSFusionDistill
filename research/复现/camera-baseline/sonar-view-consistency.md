# 换视角后的注册失配：时间、位姿与图像运动核查

2026-11-11，`sonar_view_consistency`。研究审计，不是检测模型实验。沿用6条允许开发录音；不调整已有mesh注册，不生成正式声呐框。

## 结论与证据层级

**本地时间/索引和导出位姿复算通过，但固定的相机成像参数+时间+位姿组合，尚不能可靠解释所有局部图像运动。现在不能只靠移动3D模型解决换视角失配。** 这不是“已找出唯一根因”：图像证据受平面退化影响，仍不能在采集同步、相机内参/畸变、安装外参和实测姿态中唯一定位责任。

原始产物复算：18个控制身份的SD索引、ARIS时间、Pan/Tilt/Roll与导出一致；吊架坐标最大差异`1.1991e-8 m`，所用SD副本hash匹配。17张有SD，1张缺SD保留。它排除的是这些身份的明显本地错接，**没有认证采集同步或物理标定**。

原始产物复算：同录音宽视角SIFT只有2对得到足够的F内点，未达到预登记的跨录音重复支持要求。追加已登记的局部±15 SD帧诊断：34个计划图像对中26可用、8越界保留，共43次解码访问；不替换失败，不扩大到其他录音。局部短基线通过也不能认证宽基线注册。

## 排除目标匹配后的检查

本轮继续使用已保存点对，不新增源图解码。中心帧已有独立目视轮廓外扩10px排除目标；轮廓外仍可能含支架、运动物体和误匹配，不能直接叫静态真值。26对中17对在排除后仍有≥24点。以按空间排序交替分点的八点法拟合/检查F，并比较同一检查点的固定位姿Sampson误差。**此前全部点已经参与RANSAC，因此这里是内部复核，不是独立验证集。**

22/26对目标外点可被单一homography在1.5px阈值下解释≥90%；可由近似平面、较小视差等产生。因而**没有取得预登记要求的三录音非退化相机运动证据**，不能从拟合F恢复“真实相机位姿”，也不能按上表将一项标定判死。仍可报告：部分轮廓外匹配呈现相干运动，而当前组合的对极预测偏差更大，问题调查不能只停留在mesh。

源时间量化±1 SD帧未消除若干差异。例如173329 / 1265→1280全部点的误差中位数为6.880 / 9.541 / 4.669px（−1/0/+1），101131 / 1712→1727为3.679 / 3.653 / 3.721px。这里只排查约33ms量化敏感性，**没有排除更大同步偏移、漂移或逐录音同步误差**。也没有挑最优偏移改数据。

## 相机成像参数核查

此前注册采用公开linear的K/3、零畸变，这是我方诊断假设。四组公开K仅按零畸变做敏感性对照，不等于完整的各模式标定。保留原有两fit帧、固定所有位姿，独立三角化近似两端点：

| 类别 | linear fit / 检查 RMS | 仅按fit最小的焦距倍率 | 该倍率fit / 检查 RMS |
|---|---:|---:|---:|
| bomb | 36.51 / 218.57 px | 0.50 | 29.89 / 142.75 px |
| grenade | 3.65 / 66.25 px | 0.80 | 0.66 / 65.45 px |
| mortar | 1.23 / 44.75 px | 0.90 | 0.41 / 45.01 px |

这是**端点诊断**，不是旧mesh注册读数。单独缩放焦距无法在这组控制中使检查通过；不能据此选择新K，也不能排除与畸变/外参耦合的内参问题。端点为近似目视点，跨视角同名点也有不确定性。

本地保存的[官方历史README](../../related_work/model-registration-sources/historical-README.md)明确写有GoPro SD wide fisheye参数（fx397.77/fy394.00），而当前[linear文件（本地产物说明）](../../ARTIFACTS.md#artifact-bec7e2f68af0)给FHD K及四维distortion。两者版本/模式不同，四维系数本身不能证明采用Brown还是fisheye。旧公开脚本/示例不足以确认这6条录音的实际镜头模式、畸变模型和水下适用性。本轮没有把历史wide或未知distortion强套到当前图像。

## 实际验证、失败记录与边界

- [脚本](../../tools/verify_camera_motion_evidence.py)独立从位姿重建全部26个预测F，与原局部产物的Sampson中位数差异<1e-7px；已知非共面合成控制最大误差`6.24e-14 px`，故意反转运动方向中位数`6.00 px`。这验证软件方向/公式，不验证传感器。
- 原始复算/局部诊断所记录的小输入hash均复核相同；6个视频size/mtime相同，未重新hash全部视频。先前预登记hash变化仅由本轮追加复核协议造成，旧hash和现hash均在新JSON记录；其余输入不变，旧注册产物未改。
- 首次运行在旧预登记hash处主动停止，确认唯一变化是本轮追加的协议后，显式限定该路径允许历史差异再重跑通过；没有绕过源文件变化检查。一次辅助读取因Windows默认GBK失败，改显式UTF-8；没有改源数据。
- 原仓当前HEAD仍为`4fadd06829c6c738977639a55b6e44ad0e35ac44`，status clean。没有访问原test图像、标签、预测，没有训练/推理/正式GT/新split。43次局部图像访问已计入新的开发诊断范围，不沿用“只看18帧”。

## 后续顺序

1. 先取得这批GoPro录制模式、标定分辨率、畸变模型和适用介质的可核验证据；未知项不当论文事实。若无这些记录，需要独立水下标定或已知尺度的非共面控制点。
2. 在独立相机模型固定后，用持续背景轨迹与源Pan/Tilt/Roll/gantry运动核验同步及姿态；预先定义每录音固定同步参数，不逐帧自由调位姿。当前局部平面匹配不足以同时解所有变量。
3. 相机链通过后，才用跨视角独立对应重新验收全局固定mesh→target；保持旧注册并保留所有失败。随后单独验收sonar外参、成像范围与人工QA，才准生成可信sonar框。
