# Camera-only teacher：按依赖推进的计划

2026-11-10。状态：**预登记草案，未执行训练、未生成新 split、未开封 test**。协议原则已固定，具体 manifest 和数值门槛尚待数据准入完成，不能声称实验已完全冻结。

## 0. 当前决策

保留 YOLOX-S、现有 camera-only 实现、原生 camera GT 和已完成的同录音诊断。下一步先验证 recording-level split 下的教师；暂缓 CMOLD 蒸馏、融合、容量搜索、继续扩 seed、批量增广和追论文绝对 AP。旧数据与失败实验不删除。

## 1. 数据准入，先于任何训练

目的：让每个读数都能对应固定的 camera 图像、标注、recording 与历史使用角色。输入为已获准使用的 train/dev 和录音级历史元数据，不打开原 test 的图像、逐帧标签或预测。

必须产出：数据版本、转换脚本 hash、source release、原生标签到 FHD 的坐标变换、边界框策略、recording 清单及类别/几何覆盖、逐帧 manifest、标注 hash、历史使用登记、所有排除理由。先做 train/dev 的 bbox/resize/pad 可视化和反向坐标核对。不要把原生框的裁剪当作无改动标注。

工具准入：原评测器当前只保存AR@100；将来要输出协议要求的AR@1/10，先在非test评测路径补导出与验证，或在发车前登记可执行的指标子集，不能从旧summary补造。当前cosine配置eta_min=6.25e-5而日志尾值为6.4641e-5，v1优先沿用已核实的实际配方作为参照；如修scheduler，另起单变量版本，不声称现有尾LR与论文完全一致。

停止条件：来源或坐标未确认；任一 recording 同时进入 train 与 dev；无法追溯源 recording；预期类别在 dev 缺失；存在无法解释的整类/整录音空标注；未完成目录被误当数据根。遇到这些情况只做修复与登记，不启动训练。

继承的 `prepare_camera_dataset.py` 目前暂停运行：其四条 test 仅 bomb，`excluded` 不能证明完整历史未使用，且会在同一次准备中读取并复制 test。后续版本应先独立完成 train/dev，封存 test 路径，修正历史证明和覆盖主张后再另行冻结。不得直接续跑现有 incomplete 目录。

## 2. v1_camera_recording_split：建立有效对照

| 项目 | 预登记内容 |
|---|---|
| 目的 | 得到新训练 run 在未进入该 run 训练的 recording 上的 camera-only 开发结果 |
| 核心变化 | 采用数据准入后冻结的 recording-disjoint manifest；属于新平台基准，不把旧 830-val 绝对差当单变量效应 |
| 对照 | 固定现有 t_camera_s 的模型、初始化家族与训练配方；旧帧级读数只作管线诊断参考 |
| 初始化 | COCO 起点重新训练，不能从已见全部 37 条录音的 UXO 权重继续训练；同一新平台各臂初始化相同 |
| 预算 | 初选 seed=0、200 epoch、batch=8、final epoch；单 seed 不支持稳定性结论；数据量变更的 iter 与曝光必须记录 |
| 指标 | camera、d0、GT=all、pooled mAP@[.5:.95]/AP50/AP75/AR@1/10/100，逐类和逐 recording 同报 |
| 判定 | 无 recording 重叠、完整来源链、复核几何和权重加载、没有未解释的整类/整录音失败；通过后才称开发协议上的有效基线，不设未经论证的“论文AP”硬门槛 |
| 停止 | 数据/加载/几何检查失败、非有限loss、未登记的协议变更；保留日志和失败版本，不自动换配置继续搜 |

新 dev 可能来自过去研究中已用过的 recording；只能称新 run 的 recording-disjoint development，不能追认成整个研究从未见过的数据。若沿用旧训练池的子集，新的数据规模会改变；本实验不能单独识别泄漏效应大小。

v1以epoch为主预算，数据池改变时iteration与曝光随之改变，不能同时宣称更新次数匹配。未来采样扩数据对照若选择固定更新次数，就需要调整epoch并另行登记，不把两种预算混写成全部不变。

## 3. v2_camera_geometry：仅在需要时做的受控几何对照

目的：核实几何在**新平台**上的影响；唯一变化为 keep_ratio 改为 squeeze，train/eval 同时保持一致。其他 manifest、标注、seed、初始化、预算、阈值、权重选择全部固定。对照 v1，同一 pooled 指标与逐录音失败表并报。现有 P2 已证明在旧同录音 val 有 2.8129 AP 点观测差，不足以要求立即重跑。

判定与停止：报告差值但单 seed 不宣称显著；出现任一录音全面失败需先排查坐标与置信度，不按较高平均值自动验收。不得只改 eval 几何再把掉分解释成另一种训练几何无效。

## 4. v3_camera_augmentation：证据支持才做

前提：v1 合格且仍需研究训练配方。目的为检验一种具体的 camera 增广；唯一变化与实现参数在发车前补全冻结，不能一次加入 Mosaic、HSV、多尺度等再归因。YOLOX-S 原始 recipe 本就去掉 MixUp，不能把补 MixUp 设成“恢复论文默认”的必要步骤。

对照 v1，数据/预算/seed/权重选择保持一致。选择只看开发集；多次试验全部登记。效应不稳定或出现整录音退化时，停止扩大搜索；如需确认稳定性，再对最少数量的候选做相同 seeds 的配对复验。当前不发车。

## 5. 最终测试与蒸馏入口

只有在历史隔离和三类覆盖均可证明时才建立完整三类 final test。封存后，在教师方案与模型选择规则冻结后进行一次计划好的评价；报告失败也不返回调参。若只有四条新 bomb 录音，可在后续单独命名为有限类别/条件的 external holdout，不能宣称三类教师已通过最终测试。

若没有足够可信未触碰录音：以 recording-disjoint train/dev 或 grouped cross-validation 报开发结果；预算允许时用外层评估、内层选择的 grouped CV。整个研究已受旧数据启发这一限制仍要声明。最终外部验证等新增采集/新数据，不能靠重命名旧 test 获得。

教师通过开发协议验收后才讨论蒸馏。跨模态蒸馏还需另行核实 paired 数据与标签、教师预测和初始化来源；本轮不把相机基线审计扩展成 CMOLD 机制复现实验。
