# 4081对数据：camera-only YOLOX-M与sonar-only YOLOX-S baseline方案

2026-11-13。状态：方案，未启动训练、未激活新数据执行版、未读取test图像或逐帧COCO。用户已确认当前划分，本轮要求先给方案；不重新划分、不新增数据审核门槛。此方案为我方实验设计，不作为CMOLD/CMHD论文配方陈述。

## 1. 目标与数据

建立扩充场景后的camera-only teacher和无蒸馏的单声呐学生，随后以该学生作为跨模态蒸馏的直接对照。当前目标是新版平台基准；“旧模型失败由场景单一造成”作为动机，不能仅凭新版成绩证实唯一因果。

固定输入：`DataSet/scene_stratified_mortar_recovered_candidate/`。保留4081个sample身份、框、来源组与角色。

| 集合 | 配对数 | 录音数 | 来源组数 | bomb / mortar / grenade |
|---|---:|---:|---:|---|
| train | 2472 | 21 | 17 | 966 / 800 / 706 |
| val | 894 | 9 | 7 | 310 / 272 / 312 |
| test | 715 | 7 | 7 | 308 / 246 / 161 |

以上数量来自当前summary；train/val COCO本轮重新计数一致，各模态每图1框。test只引用录音级汇总，不进行样本读取或模型评测。

train覆盖全部8种类别×摆放×运动场景，沿用用户接受标准。val/test不要求全部细条件与train一致；高度、倾角、电子设置差异继续披露。迫击炮flyby仅16train/20val/0test；普通及地面炸弹flyby为train-only，不能报告其独立留出性能。

## 2. 实验臂

| 名字 | 模型与输入 | 监督 | 作用 |
|---|---|---|---|
| scene_camera_m_baseline | camera-only teacher，YOLOX-M，原SD相机图 | 原SD camera框，全部有效GT | 后续相机教师 |
| scene_sonar_s_baseline | sonar-only，YOLOX-S，raw声呐PNG三通道复制 | 当前已接受的可见回波框 | 后续蒸馏学生的无KD对照 |

两臂训练成员和role完全对应，训练时只加载本模态，不读取另一个模态图像；关闭融合、蒸馏、退化支路。教师与学生的AP衡量不同图像和框任务，不能把教师AP减学生AP解释成可蒸馏空间。

本阶段不要求新增camera-S。若要单独研究扩量收益，后续另登记同模型、同评估成员的旧/新训练池对照，核对旧训练成员不得落入共同val，并选择固定epoch或固定更新次数预算。不能把旧S/旧val与新M/新val的差值全部归因于数据或容量。

## 3. 数据执行版准备

现目录引用其他目录，不直接拷贝此文件夹后开跑。执行时另建独立train/val副本：解析COCO的file_name时以候选根目录为基准，将相机与声呐图像复制到本模态目录，重写相对路径；保存原sample、recording、group_id、原路径、图像及标注hash。不覆盖候选、不修改原研究目录。test内容留在原位封存，本轮训练包不含test。

冻结manifest、recordings、protocol、用户划分确认和train/val COCO的hash；核对配对身份一致、来源组互斥、跨角色重复、路径可读与图框范围。不依据模型表现增删成员。保留助手标注来源与精密同步/专家认证未完成状态；单模态baseline无需新增精密跨模态注册，不把该认证变成当前训练的额外门槛。

类别唯一映射：COCO 1=bomb、2=mortar、3=grenade；模型内部0/1/2相应映射。保留源类别拼写`incindiary_grenade`，不能继承旧包bomb/grenade/mortar的编号。

## 4. 共同配方（建议值，执行前写入resolved config）

| 项目 | 方案 |
|---|---|
| 初始化 | 均从COCO预训练backbone/neck开始，三类检测head随机；不用任何旧UXO权重resume或warm-start |
| M起点 | 沿用本地已有作者YOLOX-M转换权重；加载前复核转换报告、文件hash及全部目标参数严格匹配 |
| S起点 | 沿用已有MMDetection YOLOX-S COCO权重；严格核对backbone/neck实际载入 |
| M结构 | depth .67、width .75、neck [192,384,768]→192、2个CSP block，head 192通道 |
| S结构 | depth .33、width .5、neck [128,256,512]→128、1个CSP block，head 128通道 |
| 输入 | 保持长宽比缩放到640×640内，右/底pad=114至固定640×640；train/eval一致 |
| camera | 原640×360像素保持，不拉伸，补边至640×640 |
| sonar | 保持当前raw PNG值，灰度复制为三通道；不自动增益、不翻转、不改成polar、不套用camera框 |
| 训练预算 | 200 epoch，batch 8，seed 0；FP32，全网络微调；2472/8=309 step/epoch，共61800次更新 |
| 优化器 | SGD，lr .00125，momentum .9，weight decay .0005，Nesterov，grad clip 35 |
| LR | 沿用已有5 epoch warmup、cosine至epoch185、最后15 epoch恒定的实际实现；保留原T_max=185及eta_min=.0000625，不宣称实际尾值精确等于eta_min；保存实际LR轨迹 |
| 增广 | 首轮关闭Mosaic/MixUp/HSV/随机仿射/多尺度等图像增广，沿用现有可审计配方 |
| EMA | 可维护并保存；主结果固定epoch200的真实raw，EMA只单列，不按AP择优切换 |
| checkpoint | 每10 epoch保存，另保留epoch200 raw/EMA、优化器、scheduler、RNG及完整resume状态 |
| 验证 | 每10 epoch离线val记录学习趋势，epoch200作为预定主结果；不early-stop、不切换best-val，不据曲线临时加轮数 |
| 推理 | score .01，NMS IoU .65，maxDets 100；d0，无测试时增广 |

61800次更新适用于单进程、batch8且每epoch遍历2472样本的实现；多卡等设置改变须先重算并登记，不能沿用旧45000iter元数据。M与S的COCO发布来源不同，不用于纯容量因果比较。当前M转换报告记录516张量及三层前向误差控制通过；执行前仍需核对实际文件与加载结果。

先保留无增广基准，有利于辨认新版数据上的剩余问题；无增广不是最优泛化配方的结论。若val持续出现过拟合或特定失败，下一轮按独立预登记只改变一项增广。不能因训练集拟合好而要求无限加epoch。

## 5. 发车前检查与停止条件

只对train/val执行：各类与各原生尺寸的resize/pad及框逆变换；真实batch8前后向；有限loss与梯度；本模态有效分支被更新、另一模态未输入；推理输出类别/坐标有效；GT预测控制得到预期AP，错误预测控制降低AP。检查raw/EMA的实际字段身份，不凭文件名；不要无条件硬编码历史版本的字段交换方式。

任何数据丢失、分组重叠、类别错位、坐标错误、权重不匹配、非有限loss或显存不足均停止并保留日志；不自动降batch、更换图像几何或替换数据。实施修复与参数变化另记。资源允许可并行，显存不足则串行，不以共享GPU时间当模型速度。

本轮不执行这些训练预检，不消耗训练预算。

## 6. 评价与判定

主指标为各自模态、GT=all的pooled COCO mAP@[.5:.95]，同报AP50/AP75、AR@1/10/100、图像/GT/预测数。附逐类、逐recording、逐scene的同口径表；场景组内重新pooled COCOeval，逐录音均值另列且不代替pooled AP。缺少留出样本的场景记N/A。单一类别场景只统计其有GT的类别并注明类别数。

在预先固定的train/val样本上保存GT/预测对照，检查漏检、重复/额外预测、类别混淆及框偏差；包含固定例子和失败例子，不能只挑成功图。固定epoch200另做train自评，与val用同一评价口径判断拟合和跨录音落差；不将train分数作为泛化结果。

合格条件：数据/加载/评价检查通过，主结果可复核，逐类/录音/场景异常有记录。没有预设“必须超过多少AP”的虚构门槛；整录音或整类失败必须先解释，不能被总体均值掩盖。教师只在某些场景可靠时，明确其适用范围，不因较大模型自动称强教师。

单seed先建立运行基准，不能声称稳定提升。正式蒸馏比较建议在固定配方后对student无KD/有KD使用相同0/1/2三个seed；若研究教师稳定性，教师也另补相同seed复验。当前两臂seed0不强制扩成全部6run。

声呐尺寸与采集设置可能携带类别线索，本轮不静默改图来消除。新版已出现128×780、128×441、128×603、128×771（最后一种本轮仅train元数据中出现），不能沿用旧版两尺寸统计；执行时按类别×尺寸×来源组列明关联。每图一个可见目标的筛选分布不支持纯背景误报率或真实海域泛化结论。

## 7. test及蒸馏衔接

本阶段仅train/val。两个baseline与后续蒸馏配方/模型选择规则冻结后，再按一次预登记统一评价当前715对test；test已有数据建设和研究开发历史，不能称完全未触碰的最终外部测试。原研究标记test的内容访问不因此扩大。缺失的flyby test场景继续N/A。

后续蒸馏固定同一sonar-S结构、起点、数据、预算和评价，仅新增蒸馏监督，并分别记录教师及学生checkpoint身份。相机与声呐GT位于各自坐标系，不能直接复制相机框监督声呐；是否需要时间/区域对应复核由具体蒸馏方法决定。

每run保存预登记、数据hash、代码快照hash、resolved config、环境、命令、日志/LR轨迹、checkpoint及实际加载身份、metrics、逐类/录音/场景表、失败图。结果产生后追加results.md，不写计划AP。本轮未改evaluation.md的既有执行协议。
