# sonar_projection_root_cause：固定投影错位的原因链与修正

2026-11-12。用户要求持续探究并解决明显错误，直到找到可验证原因链或边际收益很低；信息不足时提问。只在既有开发身份工作，原研究目录、原test、正式split与GT保持原状。

## 固定输入与问题

主对照为sonar_box_guided_full_trajectory，使用其相同fit/check身份与冻结标签。两类各12 fit；143同录音和338跨录音检查。检查集已用于开发，不称盲测。新出现bomb23接受框不混入本轮，另记其存在。

目前症状：mortar框跨时段不相容；grenade同录音改善而跨录音后段偏移；部分框IoU好但投影形状不合。检验必须区分软件一致、观测充分、物理链正确。

## 顺序与对照

1. 源码/元数据审计：复核官方姿态拼接、SonarPan与PanAbsPosition、时钟字段、gantry插值来源及notes。统计五录音的姿态字段差、发射设置和已有误差；字段差仅是假设，不直接替换生产标定。
2. 固定框内提取主回波range曲线：只使用已有已接受框作为身份/区域，不用新模型投影截取；高斯去噪后逐beam取峰值，背景/低信号/边缘支架分离，显式冻结图和点、目视核对fit与每条check代表帧。不把亮度峰当精确物理表面。不同transmit/gain条件分别标明。
3. 唯一改变损失的对照：固定时间、外参、尺度、同一14初值预算，在框四边损失上添加模型近表面与冻结主回波曲线的偏差。用每beam邻域range最低表面与观测比较，允许3bin误差，按框高度归一化；不逐帧改姿态。全部初值与失败保留，只按fit损失选解。
4. 如字段审计支持编码器差异，再另行登记Sonar姿态→AbsPosition对照，不与损失改变混做；只作诊断、不自动追认编码器真值。若证据指向时间，只在独立可见运动/已知空间约束下检查，不用调时间把框贴合。

## 判断

报告相同身份的框IoU、曲线range中位/90分位误差、逐录音及前中后分段，另看形状/端部与FOV。模型surface与回波峰不等同，不能只追峰降损失。定性根因必须有来源机制、可复算预测、单因素干预及未拟合身份支持；仍无法区分则明确写假设。

可部署候选需每条检查录音中位IoU≥0.5且≥80%帧IoU≥0.5，同时代表帧无系统性形状错误；门槛是我方选择。若两个有依据的单因素控制均无稳定收益（中位IoU<0.03改善或某录音下降>0.05），或需要未知同步/物理尺寸才能区分，停止无依据拟合，交付未解项与向用户提出的最小信息需求。更具体根因出现时允许追加事前登记，但不无限扩大自由度。
