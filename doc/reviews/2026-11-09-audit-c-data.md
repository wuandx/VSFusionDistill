## 2 逐条核对

### 2.1 claim 1：frame_split 三件事

**判定：成立。**

证据（A）：

- `frame_split.json`：`counts.train = 3322`、`counts.val = 830`；`val_frac = 0.2`、`seed = 0`
- 逐类：`per_class["100lbs_aircraft_bomb"] = 912/228/1140, val_frac 0.2`；`incindiary_grenade = 1061/265/1326, 0.199849`；`mortar_shell = 1349/337/1686, 0.199881`
- 复算：`train ∩ val = 0`；`train ∪ val = 4152` = `pool.frames`；逐类占比 0.1998–0.2000
- 生成器的硬断言在 `tools/make_frame_split.py:361-379`（counts 对得上、并集覆盖池、train/val 不相交、无 test 录音），逐类容差 `:387-390`（`max(0.01, 1.5/total)`），池定义 `:6-10`（只取 `split ∈ {train,val}` 的 4,152 帧/37 条），种子与比例 `:72-74`

**但必须与这条一起引用的两件事**：

1. `recordings.train` 与 `recordings.val` 各 37 条，`recordings.shared = 37` —— 同一批录音两侧都有。`make_frame_split.py:394-397` 的日志文案自己写着"frame-level random => near-neighbour leakage is expected, plan §9"。也就是说近邻帧泄漏是这套划分的已知属性，不是意外。
2. `check()` 只禁止 test 录音进划分（`:375`），没有任何"val 录音与 train 录音不相交"的断言。这是设计选择，不是漏检。

结论：数字成立；若把它当成"泛化能力"的度量，则是把已知泄漏当成了干净读数。

### 2.3 claim 3：泄漏的两个数

**判定：test 0 重叠成立；732 无法核实但量级一致；142 无法核实且与本机结构冲突。**

**（a）"test 900 与我方训练集重叠 0 帧"——成立（A）。**

- 帧级：`set(frame_split.train) ∩ {frame_meta.split == "test"}` = **0**；`set(frame_split.val) ∩ test` 也 = 0
- 录音级：test 的 10 条录音 ∩ 我方池 37 条 = **0**
- 这条结论因此在两个口径上都站得住，`doc/logs/2026-11-09-r0-first-result-and-overfit-diagnosis.md:317` 的措辞（"只有 test 能用作干净考场"）成立。

**（b）"他们 val 900 里有 732 帧（81%）在我方训练集"——无法核实（C），但本机同构复算支持这个量级（A）。**

- 本机 6,246 域复算：我方 train 3,322 帧中，落在 `frame_meta.split == "val"` 的有 **1,196** 帧，占对方 val 1,500 帧的 **79.7%**。
- 3828 平台的 val 是每条 90 帧（6,246 域是 150 帧），若按均匀抽样，期望重叠 ≈ 0.797 × 900 ≈ **717**；文档写 732（81.3%），差 15 帧，在 900 帧抽样的二项噪声（1σ ≈ 13 帧）之内。
- 结论：方向与量级成立，**精确值 732 需 3828 帧名单才能核实**；本机不能确认，也不能否认。

**（c）"val_id 378 帧里有 142 帧"——无法核实，且与本机结构有明显张力（A）。**

- 本机复算：我方 train ∩ `frame_meta.split == "val_id"` = **0**，一字不差（池定义把 594 帧 val_id 全部排除，`make_frame_split.py:6-10`）。
- 因此"142 帧重叠"要成立，前提是 3828 平台的 val_id 帧与 6,246 域的 val_id 帧**不是同一批帧**（跨平台抽样规则不同）。本机没有 3828 名单，无法验证这个前提。
- 142/378 = 37.6%，既不是 0 也不是 ~80%，本身不像任何一条已知抽样规则（80% 池内 → 期望 ~302，37.6% 处在其一半）。这条要么有特定抽样机制，要么数错，本机判不了。

**（d）一条方向相反的提醒（A）**：我方 val 830 帧里，526 帧来自对方 train、304 帧来自对方 val。所以"帧级交叉"是双向的：对方的 train/val 帧大量出现在我方的 val 里，我方的 830 也大量落在对方 train 里。任何"我方 val 是干净考场"的说法都不成立；今日文档没有这样说过（`doc/logs/2026-11-09-r0-first-result-and-overfit-diagnosis.md:324-330` 明确 R0/R2/M/P2 都含同一种乐观），这一点是自洽的。

- 我方在 0.01 阈值下几乎每帧都出框，**把阈值一路抬到 0.30，出框率也只掉 1.2 个点**。所以"两边分数阈值不同"（`doc/logs/2026-11-09-r0-first-result-and-overfit-diagnosis.md:379`）**不足以解释 94% 对 46% 的 2 倍差**：要掉一半，阈值得高到把整帧的最大分压到线下，那已经不是"阈值一档"的问题。
- 更可能的解释是**统计规则不同**：他们那 418 可能数的是"有命中（IoU≥0.5）的帧"、"score≥0.5 的帧"或经过更小 `maxDets` 截断的帧，而不是"score≥0.01 有任何框的帧"。这三种口径都与 AP 无关，但会让"出框帧数"这个指标彻底不可比。
- 本机没有他们的预测文件，无法坐实是哪一种；但从我方分布看，**"阈值不同"这个诊断大概率是错的**，至少没有证据。
- 对 AP 的影响方向：COCO AP 是对全部 recall 的精度积分，**降低 score_thr 不会抬高 AP**（它只是把低分框放进 PR 曲线尾部，精度不升、召回可能升）。所以 844 > 418 本身不构成"我方分数虚高"的机制，反而说明我方保留了更长的尾部、更保守。真正能改变 AP 的是 gt 口径与 maxDets，不是这个帧数。

**（c）这会不会动摇"都在 0.06–0.09"**

- **量级层面：不动摇。** 同一考场（他们 test 900）、同一份 1 框/帧的 GT，两份读数 0.0849 与 0.0626 都落在个位数百分比的同一数量级（`doc/logs/2026-11-09-r0-first-result-and-overfit-diagnosis.md:359-363`）。哪怕评测器细节有差，0.06–0.09 与论文 0.661 差一个数量级这个结论不受影响。
- **但这句话有两个必须加的限定：**
  1. **只对 gt=all 成立。** 同一张表 `:359-363` 的 gt=blob 列是 0.0021–0.1320（我方 R0 0.1297、我方 R2 0.1320、他们 B0 0.1129、M 教师 0.0696、他们 e09 旧配方 0.0021）。除 e09 外全部高于 0.06，最高 0.132 已经出带。`:367` 的"所有人都塌到 0.06–0.09"严格说只描述 all 列。
  2. **排序不可用。** "我方 0.0849 高于他们 0.0626"这句在同一份文档 `:381` 自己留了余地；本审计同意留余地，并且要补一句：两边评测器没能打通（`:382-383` 试图用我方评测器评他们 B0，AP 全 0，键或结构不匹配），所以**没有任何一格是"同一把尺子"量的**。"0.06–0.09 同量级"是可信的；"谁高谁低"不可用。
- 另有一条对本条不利的证据：同一个模型、同一批预测，**gt=all 与 gt=blob 差 13.6 点**（0.5347 vs 0.3989，`doc/logs/2026-11-09-r2-cmold-and-geometry-readings.md:82`）；在干净考场上方向还反过来（blob 高于 all：0.1297 vs 0.0849）。也就是说 gt 口径这个开关本身就能移动十几个点，比"0.0849 对 0.0626"这 2.2 点大一个量级。既然两边都同时报了 all 与 blob 两列，这条不构成"口径不同"的指控；但它说明这套数字对口径极其敏感，任何跨平台比较都必须两列并列引用。

### 2.6 claim 6：相机 26 点，是不是"考场难度"

**（a）两评测集是否重叠——不重叠，成立（A）。**

- 我方 830 帧 ∩ 他们 test 900 帧 = **0**（帧级；test 不在 6,246 域的任何 split 之外，我方池也不含 test）
- 录音级：test 10 条录音 ∩ 我方池 37 条 = **0**
- 所以"两组评测集不重叠"这半句成立，`doc/logs/2026-11-09-project-reaudit-vs-prior-conclusions.md:55` 的"一帧都没有"是对的。

**（b）"26 点差距是考场难度，不是模型能力"——不成立（作为单因归因）。**

把文档自己的 2×2（`doc/logs/2026-11-09-r0-first-result-and-overfit-diagnosis.md:292-297`）摆全，四个格子是这样：

| 考场 \ 模型 | 我方相机 S（letterbox 训） | 他们 E13-cam（挤压训） | 同考场差 |
|---|---|---|---|
| 我方 830 帧（帧级） | **0.9025**（A，有产物） | **0.6408**（A，有产物，挤压喂图） | **+26.2** |
| 他们 test 900（录音级） | 0.6408（C，本机无产物） | 0.6530（C，本机无产物） | −1.2 |

- **同一考场看两模型**：我方 830 上差 26.2 点，他们 900 上差 −1.2 点。若 26 点纯由"考场"造成，第一行两个数应当接近；实测不接近。文档 `:304`"同模型、同帧、同标注下差 1.2 点"只用了第二行，`:307`"两个模型的真实水平相同"也只用了第二行。
- **同一模型看两考场**：我方模型换考场 −26.2；他们模型换考场 **+1.2**（0.6408 → 0.6530）。两个模型对"换考场"的反应方向相反，说明这不是一个模型无关的难度平移，而是**模型×考场交互**。
- 结论：26 点是"换考场"这个复合操作的总效应，其成分至少有三项同时变化——帧集（我方 830 → 他们 900）、标注（我方 `camera.json` 830 框 → 他们 3,828 帧 1 框/帧）、训练曝光（见下）。把它整体命名为"考场难度"、并据此否认模型差，超出了 2×2 能支撑的范围。

**（c）训练曝光不对称（A/B，文档未提）**

- 我方 830 帧来自 37 条录音，而这 37 条**全部**在我方相机的训练集里（帧级 8:2，`frame_split.json` 的 `recordings.shared = 37`）→ 我方模型对 830 帧的近邻覆盖率 **100%**。
- 他们 E13-cam 只在他们 3828 的 train 27 条录音上训（`doc/logs/2026-11-09-r0-first-result-and-overfit-diagnosis.md:351`）→ 我方 830 帧里有 526 帧（63.4%）来自这 27 条，另外 304 帧（36.6%）来自他们的 val 录音，他们的模型没见过。
- 这层不对称的方向不是"解释掉我方 26 点优势"：我方模型在 100% 帧上有近邻，他们的模型只在 63% 帧上有近邻，结果仍是我方高 26 点。所以要么我方相机模型在我们自己的考场上确实更强，要么我方 830 的标注更容易（两份 `camera.json` 不同源），要么两者都有。**无论哪一种，"两个模型真实水平相同"都不成立。**

**（d）另一处需要回 5090 核对的疑点（C）**

- `doc/logs/2026-11-09-r0-first-result-and-overfit-diagnosis.md:295` 第 2 行"我方相机 on 他们 test 900 = 0.6408 / 0.8669 / 0.7010"，本机无产物。
- 第 4 行（`:297`）= 0.6408 / 0.9068 / 0.7028，本机产物 `results\xeval\e13cam_on_ourval_stretch\ap_summary.json` 实测 0.640766 / 0.906752 / 0.702817，逐位吻合。
- 两行 AP 在 4 位小数上同为 0.6408，而 AP50 差 4 点（0.8669 vs 0.9068）、AR 差 0.0018。AP 同到 4 位、AP50 差 4 点是可能的，但概率不高；**这一格是"26 点"整条论证的分子，必须拿 5090 上的 `ap_summary.json` 原件核**。在核到之前，26 点这个数只能是"待核"。

**（e）建议的正确表述**

> 0.9025 是帧级（同录音、近邻帧）读数，不能与任何跨录音读数相减；0.6408/0.6530 是在他们 test 900 上、两模型各自按自己几何喂图的同考场读数，两者差 1.2 点，属噪声。0.9025 → 0.6408 的 26.2 点同时换了帧集、标注与训练曝光，是"口径差"的复合量，不能单独归因为考场难度，也不能据此推断两个模型的真实水平相同。
